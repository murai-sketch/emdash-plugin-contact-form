# 問い合わせフォーム（EmDash プラグイン）

EmDash のサイトに問い合わせフォームを足す。**受け口・迷惑送信の防御・保存・運営者への通知・問い合わせた人への確認メール・保存期間の後始末・管理画面の一覧**までを1本で持ち、設定は管理画面のフォームだけで済む。

フォームの**見た目はサイト側で作る。**プラグインは受け口と中身だけを持つ（サイトごとに作りが違うので、HTML を押しつけない）。設定ページに貼れる雛形が出る。

## 入れる

```sh
pnpm add emdash-plugin-contact-form
```

EmDash の管理画面でプラグインを有効にすると、次の承認を求められる。

| 求めるもの | 何に使うか |
|---|---|
| `network:request`（`challenges.cloudflare.com` / `api.cloudflare.com`） | Turnstile の照合と、Cloudflare Email Sending の REST API |
| `email:send` | EmDash 側のメール配送を使うとき |
| 公開ルート 2本（`token` / `submit`） | フォームが札を取る先と、送信の受け口 |

有効にすると、**毎日1回の後始末（UTC 18:17 ＝ 日本時間の翌 3:17）**が登録される。

## 設定

管理画面の設定フォームから入れる。**Turnstile の秘密鍵と通知の宛先が無いあいだ、受け口は閉じたまま**（素通しのフォームを公開しないため）。

| 区分 | キー | 既定 |
|---|---|---|
| 基本 | `siteName` / `notifyTo` / `senderAddress` / `allowedOrigin` | — |
| Turnstile | `turnstileSiteKey` / `turnstileSecretKey`（暗号化） | — |
| メール | `mailProvider`（`emdash` / `cloudflare`）／`cloudflareAccountId` / `cloudflareApiToken`（暗号化） | `emdash` |
| 確認メール | `autoReply` / `autoReplySubject` / `autoReplyBody` / `autoReplyIncludeMessage` / `autoReplyMessageHeading` | 送る・写しは付けない |
| 保存と制限 | `retentionDays` / `perIpPerHour` / `perIpPerDay` / `globalPerHour` / `minFillSeconds` / `formTtlSeconds` | 365日・3/10/60回・3秒・3時間 |

`autoReplyBody` で置き換わるのは **`{{name}}` `{{id}}` `{{received}}` `{{site}}` の4つだけ。**

### メールの送り方は2通り

- **`emdash`** …… `ctx.email.send()` を使う。鍵を持たなくてよい。**EmDash 側にメール配送（Settings > Email）が設定されている必要がある。**無い場合は送られず、記録に `emdash-no-transport` が残る
- **`cloudflare`** …… Cloudflare Email Sending の REST API を直に叩く。EmDash 側に配送が無くても送れるが、**メール送信の権限だけを付けた API トークンを預けることになる**（暗号化設定に入る。`EMDASH_ENCRYPTION_KEY` が必要）

### 接続元（IP）について

**IP そのものは保存しない。**回数制限の鍵には、プラグインが自分で作った秘密の塩を混ぜたハッシュだけを使う。

ただし**接続元が取れない要求は受け付けない**（制限がかけられないため）。Cloudflare の上で動いていれば自動で取れる。別の構成（リバースプロキシの後ろなど）では `EMDASH_TRUSTED_PROXY_HEADERS` に信用するヘッダ名を宣言する。偽装できるヘッダを信用しない作りなので、**宣言が無いとすべての送信が落ちる。**

## サイトに貼る

設定ページに、いまのサイトキーと受け口の URL が入った雛形が出る。要点は3つ。

1. 札（`_t`）を `…/token` から**ページを開いたときに**取る（これで「開いてから送るまでの時間」が測れる）
2. Turnstile のウィジェットを置く
3. 罠の欄（`website`）を **CSS で隠す**（`hidden` 属性だと機械にも分かる）

送信先は `POST …/submit`、`application/x-www-form-urlencoded`。返るのは `{ "ok": true }` か、`{ "ok": false, "error": "…", "fields": { … } }`。

## 防御の順番

**安いものから先に落とす。**Turnstile の照合は Cloudflare への往復が1回あるので、形も通っていない要求にそれを使わない。回数制限は Turnstile より前に数える（失敗も数えないと総当たりが無料になる）。

```
1 設定が足りない        → 受け付けない（開ける方へ倒さない）
2 Origin が違う         → 弾く
3 form が読めない       → 弾く
4 罠の欄が埋まっている  → 弾く
5 札が無い・偽・速すぎ  → 弾く
6 入力の不備            → 欄ごとの文面を返す（利用者が直せるのはここだけ）
7 回数制限              → 弾く
8 Turnstile が不合格    → 弾く（往復が落ちたときも通さない）
9 保存 → 通知 → 確認メール
```

**失敗の理由は、利用者が直せるもの（入力の不備と期限切れ）だけ返す。**それ以外は同じ文面にする。

## 確認メールで守っていること

宛先が**利用者の入力**である点が通知と決定的に違う。

| 守り | 理由 |
|---|---|
| 件名に入力を混ぜない | 受信箱の見た目を他人に作らせないため |
| **本文の写しは既定で付けない** | 付けると「Turnstile を通せる人が、**選んだ宛先へ、選んだ文章を、あなたのドメインの差出人で**届けられる」ことになる |
| 置き換えは関数で1回だけ | 名前に `$&` や `{{id}}` を入れても出力が崩れない／二重展開しない |
| 保存 → 通知 → 確認メール の順 | どれが失敗しても問い合わせを落とさない。失敗は記録に理由付きで残る |

`autoReplyIncludeMessage` を on にすると、設定ページが警告を出す。

## 管理画面

- **ダッシュボードのウィジェット** …… 未読の数と直近の1件
- **「問い合わせ」** …… 一覧（受付・お名前・メール・状態・本文の先頭）、1件を開くと全文とメールの結果、既読／未読、削除
- **「設定」** …… 足りない設定、いまの値、サイトに貼る雛形

**返信はしない。**このプラグインから返信を送れるようにしていないのは、送った記録が残らないため。通知メールの返信先に送信者のアドレスが入っているので、ご自身のメールソフトから返す。

## 保存期間

`retentionDays` を過ぎた問い合わせを毎日消す（`0` なら消さない）。**プライバシーポリシーに書いた期間と必ず揃える**——書いたとおりに消えなければ文面が嘘になる。

走った記録は `state:lastPurge`（日時・削除件数・成否）に残る。**件数だけでは「0件だった」と「動いていない」の区別がつかない**ため。

## 開発

```sh
pnpm install
pnpm run validate     # マニフェストの検証（ネットワーク不要）
pnpm run typecheck
pnpm run test         # 本番の境界を通した試験 49通り
pnpm run build
```

試験は `createPluginRuntimeTestHost()` を使い、実際の権限・公開ルート・ストレージ・メール配送・定期実行を通す。外への往復は `host.http.respond()` で差し替える——**これは1回使うと消える待ち行列**なので、呼ぶ回数だけ積む。

試験は Cloudflare の上で走らないため、`vitest.config.ts` で `EMDASH_TRUSTED_PROXY_HEADERS=cf-connecting-ip` を宣言している（本番の Cloudflare では不要）。

## 公開する前に

- **`emdash-plugin.jsonc` の `publisher` は仮の DID。**`pnpm run login` で Atmosphere アカウントに入り、本物の DID に差し替える
- `author` と `security` を実際の連絡先に直す
- `capabilities` と `allowedHosts` を増やすと、**入れている人の再承認が必要になる**

## 預かった秘密を消す

秘密の欄（Turnstile の秘密鍵・Cloudflare の API トークン）は、**空のまま保存しても変わりません。**
他の項目だけ直せるようにするためですが、そのままでは**一度入れた鍵を消す口がどこにもありません。**
要らなくなった鍵を預かり続けることになるので、設定ページに「消す」ボタンを置いています。

**空のまま保存したときの扱いは、欄によって違います。**

| 欄 | 空で保存すると |
|---|---|
| 秘密の欄（secret_input） | **変わらない**（消すには「消す」ボタン） |
| それ以外の欄 | **空が保存される** |

消すと、保存されている値は**空文字を暗号化したもので上書きされます。**
行そのものは残りますが、**鍵の中身はデータベースから消えます**（印を立てるだけではありません）。

**`EMDASH_ENCRYPTION_KEY` が必要です。**秘密の設定は読み書きのどちらも暗号化を通り、
**空にするときも通ります。**鍵が無いサイトでは消せないので、その場合は画面にそう出ます
（原因の分からない 400 を返さないため）。

## サンドボックスの呼び出し回数（必読）

**1回の実行でホストを呼べるのは10回まで**です（`@emdash-cms/cloudflare` の
`DEFAULT_LIMITS.subrequests = 10`。EmDash の設定からは変えられません）。

**11回目は返ってきません。**例外も投げず、ただ止まります。そこで待っているあいだに
実行ごと畳まれるので、`try/catch` でも `setTimeout` でも捕まえられず、
**何の記録も残りません。**保存だけ済んでメールが出ない、という形で表に出ます。

**ローカルの `wrangler dev` には上限がありません**（EmDash の
「Local development enforces no Worker limits」）。**ローカルで通ることは、
本番で通る証拠になりません。**

送信1回ぶんの内訳（9回。予備1）：

| | 回数 |
|---|---|
| `settings.list()` | 1 |
| `kv.list()`（秘密と数えをまとめ読み） | 1 |
| 回数制限の書き戻し（IP・全体） | 2 |
| Turnstile の照合 | 1 |
| 保存 | 1 |
| 通知メール | 1 |
| 確認メール | 1 |
| メール結果の書き戻し | 1 |

**`ctx.log` も1回に数えます。**ここが落とし穴です。ログは「ついで」に見えますが、
ホストへの呼び出しそのものです（`sandbox/index.mjs` の `log` は `bridge.log` を呼ぶ）。

```js
const log = {
  info:  (msg, data) => bridge.log("info",  msg, data),
  error: (msg, data) => bridge.log("error", msg, data),
};
```

**失敗したときだけログを書くと、失敗したときだけ上限を超えます。**
2026-11-01、メールの失敗を2回ログへ書いていたため、成功する場合は9回で収まり、
**失敗する場合だけ11回**になって、理由を書いた記録の書き戻しが拒否されました。
失敗の記録が、失敗のときだけ消えていたことになります。
だから**失敗の理由は記録に書き、ログには書きません。**

**ここに1つ足すときは、どれかを削ってください。**数え直さずに足すと、
症状の出ない壊れ方になります。**うまくいく場合だけでなく、失敗する場合も数えてください。**

試験のホストには上限がないので、これは試験では出ません。`tests/budget.test.ts` が
**ソースの書き方として**見張っています（メールの段と設定の保存にログを書かせない）。
